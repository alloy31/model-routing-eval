# 서브에이전트 모델 배분 실험

AI 코딩 에이전트가 작업자(서브에이전트)를 띄울 때 어떤 모델에 맡길지를 감이 아니라 측정으로 정한 기록입니다.
Claude 모델 4개(Haiku 5.5, Sonnet 5.5, Opus 5.5, Fable 5.2)에 과제 31개를 풀게 하고 통과 여부, 비용, 시간을 쟀습니다. 기간은 2026-11-15\~19입니다.

> **English summary.** I measured which Claude model a coding agent should delegate each kind of subtask to. Four models ran 31 tasks in isolated headless Claude Code sessions, graded by hidden tests or blind review. My predictions written before the runs overestimated the required model on 15 of 19 tasks. The outcome is a four-row delegation rule that I now use daily. Everything needed to rerun it is in this repository.

## 결론

**결과를 확인할 수 있는 일은 가장 싼 모델로도 거의 다 통과했습니다. 모델 등급이 품질을 가른 곳은 정답이 없는 종합 글과 도구 없이 푸는 긴 추론뿐이었습니다.**

네 모델이 모두 실행한 과제 20개의 결과입니다(effort high, 격리 실행, 여러 번 돌린 과제는 전부 통과해야 통과로 셈).

| 모델 | 통과 | 비용 합계 | 시간 합계 |
|---|---|---|---|
| Haiku 5.5 | 18/20 | $0.79 | 29.6분 |
| Sonnet 5.5 | 18/20 | $3.59 | 41.3분 |
| Opus 5.5 | 17/20 | $7.29 | 33.6분 |
| Fable 5.2 | 20/20 | $11.23 | 30.8분 |

비용은 Claude Code가 보고한 값이고, API 정가로 환산한 추정치입니다. 과제별 표는 `python3 analyze.py`로 볼 수 있습니다.

## 왜 했나

제 작업 기록을 보니 최근 14일 동안 작업자에게 맡긴 일이 66건이었습니다. 그중 Agent 도구로 띄운 41건 가운데 36건은 모델을 지정하지 않아서 메인 세션의 모델을 그대로 물려받았습니다. 가장 비싼 모델로 조사 5건과 보고서 1건을 돌린 한 번의 작업이 약 $34였습니다.

어떤 일에 어떤 모델이 필요한지 저는 근거 없이 짐작하고 있었습니다. 그래서 짐작을 먼저 적어 두고 실제로 재 보기로 했습니다.

## 어떻게 쟀나

- **사전 예측.** 실행 전에 과제별로 "통과하는 가장 낮은 모델"을 적었습니다([prereg.md](prereg.md)). 보정 세트 10개를 먼저 돌려 예측을 고친 뒤 검증 세트 9개를 돌렸습니다.
- **격리 실행.** [harness.py](harness.py)가 과제마다 빈 작업 폴더에서 Claude Code를 headless로 실행합니다. 개인 설정, 플러그인, MCP는 끄고, 채점기와 숨은 테스트는 모델이 볼 수 없는 곳에 둡니다.
- **채점.** 과제마다 `grade.py`가 숨은 테스트나 정답 대조로 통과를 정합니다. 정답이 없는 조사·보고서 과제는 모델 이름을 가리고 세 모델이 심사했습니다([judge.py](judge.py)).
- **과제.** 사실 조회, 사양 구현, 디버깅, 코드 리뷰, 사양의 모순 찾기, 도구 없는 추론, 대형 구현(정규식 엔진, SQL 엔진), 실제로 맡겼던 웹 조사와 종합 보고서를 다시 실행하는 과제로 구성했습니다. 코드 과제는 실험용으로 만든 가상 저장소(`fixtures/shiplane`)를 씁니다.

## 예측과 달랐던 것

**1. 필요한 모델을 계속 높게 잡고 있었습니다.**
예측한 19개 과제 중 15개에서 실제로는 더 낮은 모델이 통과했습니다. 낮게 잡은 경우는 없었습니다. Opus가 필요하다고 본 "낡은 문서와 틀린 전제가 섞인 다중 파일 조사", "숨은 결함 3개 찾기", "사양의 모순 2곳 찾기"를 Haiku가 3회 중 3회 통과했습니다.

**2. 도구 없는 추론은 등급 순서대로 되지 않았습니다.**
3×5 격자 타일링 수를 세는 과제에서 Haiku와 Fable은 통과했고 Sonnet과 Opus는 틀렸습니다. Opus는 effort high에서 생각 토큰을 14개만 쓰고 계산한 것처럼 답했습니다. effort를 xhigh로 올리자 7개 중 6개를 맞혔습니다. 도구 없는 추론 과제 16개를 전부 통과한 모델은 Fable뿐이었습니다.

**3. 자동 지표가 품질을 구별하지 못했습니다.**
웹 조사 과제에서 "요구 항목 26개가 들어 있는가"를 세었더니 Haiku도 26/26이었습니다. 그런데 익명 심사에서는 Haiku가 4.4\~5.0점, Fable이 8.6\~9.0점이었습니다. 키워드 포함 수는 지표에서 뺐습니다.

**4. 지침 한 줄이 모델 차이보다 컸습니다.**
조사 지침에 있던 "도구 호출 15회 이내"를 Haiku는 그대로 지켜서 요청한 범위의 절반 이상을 조사하지 않았습니다. 이 한 줄을 지우고 다시 돌리자 Sonnet이 도구를 61회 쓰고 심사 1위(9.2점)가 됐습니다. 상한이 있던 때의 Fable 원본(8.4점)보다 높았습니다.

**5. 실제 설정에서는 싼 모델이 그만큼 싸지 않았습니다.**
제 평소 설정(전역 지침, 플러그인 13개, 스킬 59개)을 그대로 실으면 호출마다 10만\~20만 토큰이 고정으로 들어갑니다. 격리 실행에서 $0.01\~0.02이던 Haiku 과제가 $0.34\~0.62가 됐습니다. Sonnet과 비교하면 약 2배 쌀 뿐이었고 약 4배 느렸습니다. 작업 폴더 밖에 파일을 만들고 `rm -rf`와 `pkill -f`를 쓴 모델도 Haiku뿐이었습니다.

**6. 종합 글에서는 등급 순서가 그대로 나왔습니다.**
조사 노트를 읽고 개인 게임 프로젝트의 설계에 주는 교훈을 쓰는 보고서 과제에서, 심사자 셋이 모두 Fable 9.2 > Opus 8.6\~8.8 > Sonnet 8.2\~8.6 > Haiku 7.0\~8.0 순으로 매겼습니다. 차이는 주로 교훈 부분의 깊이에서 났습니다.

## 그래서 정한 규칙

| 맡기는 일 | 모델 | effort |
|---|---|---|
| 결과를 테스트·실행·원문 대조로 확인할 수 있는 일 (구현, 테스트, 디버깅, 문서 반영, 사실 확인) | Sonnet | medium |
| 자료 수집 (웹 조사, 읽기 전용 감사). 도구 호출 횟수에 상한을 두지 않는다 | Sonnet | xhigh |
| 결과를 확인할 수 없고 판단이 품질을 좌우하는 일 (설계 비평, 종합 분석) | Opus | xhigh |
| 그중 제가 직접 읽고 결정하는 최종 산출물, 제 이름으로 나가는 글, 도구 없는 긴 추론 | Fable | xhigh |

- 분류 기준은 [rubric_v2.md](rubric_v2.md)입니다. 어렵고 쉬움이 아니라 "결과를 확인할 수 있는가"로 가릅니다.
- 이 기준으로 실제 위임 60건을 분류하게 했더니 제 분류와 Sonnet 59건, Opus 59건, Haiku 57건이 일치했습니다.
- Haiku는 표에서 뺐습니다. 격리 실행에서는 가장 쌌지만 실제 설정에서는 5번의 이유로 이점이 작았습니다.
- 검증에 실패하거나 작업자가 막히면 한 단계 위 모델에 다시 맡깁니다.

## 한계

- 과제 대부분을 한 번씩만 돌렸습니다. 반복한 것은 일부입니다(Haiku 9개 과제 3회씩 등).
- 과제는 제가 만들었고 제 작업 종류에 맞춰져 있습니다. 다른 사람의 작업에 그대로 맞는다고 볼 수 없습니다.
- 심사자가 평가 대상과 같은 계열의 모델입니다. 사람 심사는 없었습니다.
- 인용 대조는 모델마다 10건 표본입니다.
- "실패하면 한 단계 위 모델로" 규칙은 실험에서 실패가 나오지 않아 써 보지 못했습니다.
- 메인 세션을 어떤 모델이 이끌 때 나은지는 재지 않았습니다.
- 2026년 11월의 모델과 가격 기준입니다. 새 모델이 나오면 다시 재야 합니다.
- 전체 비용은 하네스 기록 합계로 약 $50, 심사를 포함하면 약 $58로 추정합니다.

## 다시 돌리기

Claude Code CLI가 필요합니다. 모델이 쓰는 작업 폴더는 이 저장소 옆 `mr-work/`에 생기니 끝나면 지웁니다.

```bash
# 확인 가능한 과제
python3 harness.py --tasks r1,r2,i1,i2,i3,z2,d1,d2,d3,v1,a1 --models sonnet --effort high --par 4
# 도구 없는 추론 (high와 xhigh를 따로 잽니다)
python3 harness.py --tasks x1,x2,x3,x4,x5,x6,x7,x8,x9,y1,y2,y3,y4,y5,y6,y7,y8 --models sonnet --effort xhigh
# 표 다시 뽑기
python3 analyze.py
```

## 저장소 구성

| 경로 | 내용 |
|---|---|
| `harness.py` | 과제 × 모델 × effort 실행과 채점 |
| `judge.py` | 조사·보고서 과제의 익명 심사 |
| `analyze.py` | 과제별 표, 예측 대조, 정책 비교 |
| `prereg.md` | 실행 전에 적은 예측과 절차 |
| `rubric_v2.md` | 위임 작업 분류 기준 |
| `tasks/` | 과제 31개 (지시문, 채점기, 숨은 테스트) |
| `fixtures/` | 코드 과제용 가상 저장소 |
| `results.jsonl` | 유효 실행 178건 |
| `results_invalid.jsonl` | API 오류 등으로 무효 처리한 실행 63건 |
| `replay/` | 조사·보고서 과제의 모델 출력물, 익명 심사 점수, 인용 대조 결과 |
| `FINDINGS.md` | 실험 중에 적은 작업 메모 원본 |

`tasks/w2`(종합 보고서)는 개인 프로젝트의 조사 노트와 설계 문서를 입력으로 읽습니다. 그 입력 파일은 이 저장소에 없어서 w2는 그대로 다시 돌릴 수 없습니다. 출력물과 심사 결과는 `replay/`에 있습니다.

실행 기록의 임시 경로는 `<session-tmp>`, `<scratch>`로 바꿨습니다.
